# 02 — 商品「隐藏 / 恢复」语义

## 1. 先明确一件事：本仓库不做「在闲鱼下架 / 删除」

全量检索项目源码里的 MTOP 接口清单（31 条），**没有**
`mtop.idle.item.offline`（下架）也没有 `mtop.idle.item.delete`（删除）；
`app/product_automation.py` 的 `product_delete_rules` 只支持 `dry_run` 预演：

```python
if mode != "dry_run":
    raise ValueError("当前版本仅支持 dry_run 预演")
```

所以本仓库里所有「删除」按钮的语义都只有一个：**仅在本界面隐藏**。
面板上的删除弹窗文案已按此改写，不再暗示会去闲鱼侧动商品。

> 想真正下架，需要另外写客户端 + 实测签名（另一个项目 `bixipeng/Xianyu-Auto` 用了
> `mtop.idle.item.offline` / `.delete`，接口信封见其 `src/core/client.ts`），
> 属于新的逆向任务，不在本仓库范围内。

## 2. 「隐藏」是怎么生效的

问题背景：商品同步是**周期性拉取**（默认 10 分钟一次）。如果你只是删掉本地记录，
下一次同步就会把商品**又写回来**。

解法是**墓碑（tombstone）**：

```
点击「隐藏」
  └─ DELETE /items/{cookie_id}/{item_id}
       └─ db_manager.delete_item_info()
            ├─ 删掉 item_info 里的行
            └─ 往 deleted_items 写一条墓碑（含商品快照）

之后每次同步
  └─ db_manager.save_item_info(..., allow_deleted=False)
       └─ 命中墓碑 → 跳过写回        ← 商品不会回来
```

### 墓碑表结构

```sql
CREATE TABLE IF NOT EXISTS deleted_items (
    cookie_id    TEXT NOT NULL,
    item_id      TEXT NOT NULL,
    deleted_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    absent_since TIMESTAMP,      -- 商品在闲鱼侧已消失的起点
    item_title   TEXT,           -- 快照（供「已隐藏商品」列表显示）
    item_price   TEXT,
    item_image   TEXT,
    PRIMARY KEY (cookie_id, item_id)
);
```

- 三个快照列是**后加的**：老库用 `ALTER TABLE ADD COLUMN` 幂等补上，老行保持 `NULL`。
- 前端遇到 `NULL` 时退化为显示 `item_id`。

### `absent_since` 是干什么的

同步校准阶段调用 `mark_tombstone_absent(cookie_id, on_sale_item_ids)`：

| 情况 | 动作 | 含义 |
| --- | --- | --- |
| 墓碑商品**还在**闲鱼在售列表里 | 清空 `absent_since` | 用户删的是还在卖的商品 → 墓碑要一直挡着 |
| 墓碑商品**不在**在售列表里 | 记 `COALESCE(absent_since, now)` | 商品在闲鱼侧真的没了 |

商品长期缺席（默认 `item_tombstone_ttl_days = 30` 天）后，
`cleanup_item_tombstones(ttl_days)` 会删掉墓碑 —— 否则用户日后重新上架同一商品时，
会莫名其妙看不到它。

> 约束：`mark_tombstone_absent` 只在「**完整且成功**」的同步之后调用，
> 否则会把还在售的商品误记成缺席。

## 3. 接口

| 方法 | 路径 | 作用 | 响应 |
| --- | --- | --- | --- |
| `GET` | `/items` | 在售商品列表 | `{"items": [...]}` |
| `DELETE` | `/items/{cookie_id}/{item_id}` | **隐藏**（删本地行 + 写墓碑） | `{"message": "商品信息删除成功"}` |
| `DELETE` | `/items/batch` | 批量隐藏 | — |
| `GET` | `/item-tombstones?cookie_id=` | **已隐藏商品列表** | `{"success": true, "items": [...]}` |
| `DELETE` | `/item-tombstones/{cookie_id}/{item_id}` | **恢复**（删墓碑） | `{"message": "已恢复，商品将在下次商品同步后重新出现…"}` |

⚠️ `GET /item-tombstones` 返回的是 **`{"success": true, "items": [...]}`**，
**不是裸数组** —— 前端照 `/cards` 的写法抄会拿到 `undefined`。

权限：两个接口都校验 `cookie_id` 属于当前登录用户，否则 `403`。

## 4. 前端

| 位置 | 内容 |
| --- | --- |
| 商品列表 · 删除按钮 | 弹窗语义澄清为「**仅在本界面隐藏**」 |
| 商品列表 · 工具栏 / 页签 | 新增「**已隐藏商品（N）**」入口 |
| 已隐藏列表 | 每行显示 标题 / 价格 / 图片 / 隐藏时间；快照为空则退化显示 `item_id` |
| 已隐藏列表 · 每行 | 「**恢复**」按钮 → `DELETE /item-tombstones/{cid}/{iid}` |

对应前端函数（`frontend/services/api.ts`）：

```ts
getItemTombstones(cookieId?)      // GET  /item-tombstones    → 取 .items
restoreItem(cookieId, itemId)     // DELETE /item-tombstones/{cid}/{iid}
```

## 5. 恢复流程

1. 打开「已隐藏商品」页签 → 找到商品 → 点「恢复」。
2. 后端 `clear_item_tombstone()` 删掉墓碑行 → 返回提示「已恢复，商品将在下次商品同步后重新出现」。
3. 等下一次周期同步（默认 ≤10 分钟），或手动点「同步商品」立即刷新 —— 商品重新出现在列表里。

**「隐藏」与「恢复」是成对可回滚的**：恢复后同步能重新写回，不会留下任何痕迹。

| 键 | 默认 | 说明 |
