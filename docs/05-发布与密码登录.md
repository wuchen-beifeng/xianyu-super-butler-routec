# 05 — 发布与密码登录（四期 v4 新增用法）

四期（2026-10-10）把三期做好的「能写」能力从隐蔽的图标按钮**搬到显眼的表单**，
并补一个「密码登录测试」入口。**本期只做加法**：没有任何模块 / 路由 / 前端入口被删除，
定时通道（白名单自动跑）继续保留，默认关。

---

## 1. 填表直接发布（商品自动化 → 素材库）

### 1.1 入口

「商品自动化」（侧栏「自动化」分组）→「素材库」tab → 右上角**「新建素材 / 直接发布」**。

> 三期的发布入口是素材行上一个**纯图标**纸飞机，而且素材库为空时整张表根本不渲染 ——
> 结果是「功能实现了但看不到」。四期把这个入口搬到了工具栏上，并给图标按钮加了文字。

### 1.2 表单字段

| 字段 | 说明 |
| --- | --- |
| 账号 | 下拉，取自账号列表。**图片会传到这个账号的闲鱼图床**，所以必须选对 |
| 标题 | 必填 |
| 描述 | 可空 |
| 价格 | 可空（留空 = 0 元） |
| 图片 | **上传本地文件（可多张）**，直接传到所选账号的闲鱼图床 |
| 状态 | 固定 `ready`（「待发布」）—— 省掉三期那步「打开编辑弹窗手动改状态」 |

### 1.3 提交后发生什么

```
1) 每张图 POST /xianyu-image（multipart: file + form cookie_id）
      └─ utils/image_uploader.ImageUploader(账号cookie).upload_image(本地路径)
      └─ 返回 {url, width, height, size} —— 闲鱼 CDN 链接
2) POST /product-automation/materials  ← 新建素材
      └─ 插一行 product_materials，source_item_id = manual-<uuid12>，publish_status = 'ready'
3) POST /product-automation/materials/{id}/publish/prepare   ← 发一次性确认令牌（TTL 300s）
4) 弹二次确认 → POST /product-automation/materials/{id}/publish
      └─ utils/item_publish.publish_item()（L1 协议 mtop），过 utils/write_guard 写限流
```

第 3/4 步就是三期既有的发布链路，四期没有改它。

### 1.4 关键点

- **图片必走所选账号**：`ImageUploader` 拿账号 cookie 上传，图床归属该账号。
  跨账号能不能直接用别人图床的链接**未核实**，不要假设（素材库里的 CDN 链接在跨账号发布时
  会先「下载 → 重传」，见 `ProductAutomationService._resolve_images`）。
- **临时文件用完即删**：`POST /xianyu-image` 把上传内容落到 `tempfile.mkdtemp()` 下的临时文件，
  `finally` 里 `shutil.rmtree`。
- **失败文案是明确的**：格式不支持（非图片 / 扩展名不在白名单）、文件过大（> 20 MB）、
  账号 Cookie 失效（闲鱼侧返回空 url）分别有各自的提示。
- **写限流照旧**：发布是一次 mtop 写操作，走 `utils/write_guard`（默认 1 次/分钟、每日 20 次）。

## 2. `publish_dry_run` 默认值改了（**重要**）

| 键 | 位置 | 旧默认 | 新默认（四期） |
| --- | --- | --- | --- |
| `publish_dry_run` | `system_settings`（`system_settings` 表） | `true`（缺失 = 只组装 payload） | **`false`（缺失 = 真发布）** |

两处读取点都必须同源，四期一起改了：

- `app/product_automation.py` → `ProductAutomationService.publish_dry_run()`（`prepare_publish` /
  `execute_publish` 用它）
- `utils/item_publish.py` → `_is_dry_run()`（`publish_item` 用它）

取值规则（两处一致）：

| 取值 | 结果 |
| --- | --- |
| 键**缺失**（`None`） | `false` → **真发布** |
| `1` / `true` / `yes` / `on` / `y` | `true` → dry-run（只组装 payload） |
| `0` / `false` / `no` / `off` / `n` | `false` → 真发布 |
| 空串 / 其它非法值 | `true` → 安全侧（**不**在配置写错时误发真实商品） |
| 读库异常 | `true` → 安全侧 |

要临时预演：

```bash
curl -X PUT http://<VM102_IP>:8080/system-settings/publish_dry_run \
     -H "Authorization: Bearer <面板 token>" -H 'Content-Type: application/json' \
     -d '{"value":"true"}'
```

面板「设置 → 写操作限流」区块顶部有一块显眼的 `publish_dry_run` 说明，
「商品自动化 → 素材库」的发布确认弹窗也会显示当前是否 dry-run。

## 3. 删除单个商品（商品自动化 → 商品管理）

### 3.1 入口

「商品自动化」→ **「商品管理」** tab（新增）。列表数据源是 `item_info` 表（商品同步写入），
可按账号过滤 + 关键词搜索。每行右侧**「删除」**。

### 3.2 二次确认

```
POST /product-automation/items/{cookie_id}/{item_id}/delete/prepare
   └─ ConfirmTokenStore.issue(resource = "item:<cid>:<iid>", action = "item_delete")
   └─ 返回 {confirm_token, item_title, require_text(商品 ID 后 4 位), summary}
→ 弹 ConfirmDialog（danger，requireText = 后 4 位）
POST /product-automation/items/{cookie_id}/{item_id}/delete
   └─ 校验并消费令牌 → utils/item_delete.delete_item()（com.taobao.idle.item.delete v1.1）
   └─ 成功 → 同步删掉本地 item_info 行（复用二期 T6 墓碑机制，防同步写回）
```

### 3.3 语义

**实测是「真删除」，不是下架**：调用成功后商品从在售列表消失，`pc.detail` 回
`FAIL_BIZ_ITEM_DEL_NOT_FOUND`。删除**不可逆**。返回值里带 `semantics` 字段说明这件事。

> ⚠️ 面板「商品与发货 → 商品列表」里的「删除」按钮语义完全不同 ——
> 那是**仅在本界面隐藏**（写墓碑 `deleted_items`，不碰闲鱼）。两个删除别混。

> ⚠️ 测试请用**0 件在售**的账号；主号勿动。

## 4. 密码登录测试（账号管理）

### 4.1 入口

「账号管理」页右上角 → **「密码登录测试」**（在「扫码添加账号」左边）。

### 4.2 与「自动触发」的区别

| | 触发条件 | 用途 |
| --- | --- | --- |
| **自动**（三期 W6） | 免密刷新（cookie 续期）**连续失败**达到 `pwd_login_fail_threshold`（默认 5）次，且未被冷却 / 未停手 | 无人值守恢复掉线账号 |
| **手动**（四期，本入口） | 人手点一次 | **验证链路是否通**、复现问题 |

面板会轮询 `GET /password-login/check/{session_id}` 并显示四种状态：

| 状态 | 面板表现 |
| --- | --- |
| `processing` | 「进行中（真机登录流程最长约 240 秒）…」 |
| `success` | 「成功：Cookie 已更新，账号已恢复监听」，同时刷新账号列表 |
| `need_manual` | 「需人工处理：人脸 / 短信验证，已推 QQ 通知」+ **显示截图**（后端 `screenshot_url`） |
| `failed` | 显示失败原因 |

### 4.3 状态相关配置（设置 → 账号密码自动登录）

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `pwd_login_enabled` | true | 总开关 |
| `pwd_login_fail_threshold` | 5 | 免密刷新连续失败几次触发自动登录 |
| `pwd_login_cooldown_minutes` | 30 | 触发后的冷却 |
| `pwd_login_status:<cookie_id>` | — | 最近结果：ok / need_manual / failed / blocked / preflight |

`POST /password-login/reset-cooldown` 可重置某账号的失败计数与冷却（面板上也有按钮）。
